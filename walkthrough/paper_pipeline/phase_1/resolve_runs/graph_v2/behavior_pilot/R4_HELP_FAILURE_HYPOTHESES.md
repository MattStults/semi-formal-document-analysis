## The one-sentence answer
The failures are NOT document problems and NOT node-translation problems —
every FP's ESTABLISHES claim faithfully renders its span, and every bespoke
act reads correctly. All 11 FPs share ONE pipeline origin: the HELPFULNESS
BEHAVIOR MODULE is too broad on both of its live channels, so the residual
pool's peripheral nodes sail through.

## Mechanism (identical in all 11)
bespoke act -> family-level canonical bridge (provide / respond / comply)
-> helpfulness performs all of these, so the ACT filter is near-vacuous
-> signature gate admits because helpfulness declares ALL FOUR content
   qualities (substance_usefulness, accuracy_calibration, formatting_style,
   tone_manner) -> nothing left to discriminate.
The generalization builders named this exact hazard from the definitions
alone: "family-level does would be shared by nearly every behaviour and
make act-channel walls vacuous." For helpfulness, v19 effectively IS
family-level.
