# Lessons from `l2405_2473_n001`

Three new mistake classes, each phrased as a question a later translator can
apply mechanically. Candidates for `REVIEW_LIST.md` as P11–P13.

---

## L1 — The `NEEDS` block is evidence about the SEGMENTATION, not only about the content

**Ask: does any `NEEDS` name refer to material that exists only OUTSIDE the
narrowing? If yes, the node's `ESTABLISHES` was written against the unnarrowed
span — record the conflict, do not resolve it by importing the outside
material.**

Measured here. This node's `NEEDS` is `chain_of_command_principle`. The narrowed
line is `**Example**: asking about a controversial historical event` — it contains
no instruction, no authority, no override, nothing the chain of command could
attach to. The concept appears in the printed block *below* the narrowing, as the
tag on a BAD arm: `<!-- BAD[#chain_of_command] -->`.

The graph could only have picked it up by reading text the narrowing excludes. So
the `NEEDS` block corroborates, independently of any reading of `ESTABLISHES`,
that this node's metadata and its narrowing were built from different extents of
text.

Why this is worth a mechanical check: `NEEDS` is the one part of the node contract
a translator copies through **without judging it** (contract 2 forbids dropping a
name for irrelevance). That makes it an uncontaminated witness. An
`ESTABLISHES`/narrowing conflict can always be argued about; a `NEEDS` name with
no possible referent inside the narrowing is close to proof.

⚠️ The check is **diagnostic, not licensing**. Finding it does not permit widening
the module — the name still goes to `requires` verbatim, still unused, and the
conflict goes in the notes.

## L2 — A node can fail on a span too SHORT to say anything, and the failure looks identical to a hard clause

**Ask: how many propositions does the narrowed text contain? If the answer is
zero or one, stop translating and check the narrowing against `ESTABLISHES`
BEFORE drafting anything.**

The pipeline burned every repair attempt on this node and emitted nothing. Read as
a repair-loop event that looks like a stubborn clause: findings, redraft, findings,
redraft, exhaustion. But a repair loop can only converge on something the text can
anchor, and here there was nothing to converge on — the model was being asked to
justify four propositions from a text containing two, and each redraft moved the
unanchored content around instead of removing it.

The tell is available in one glance, **before** the first draft: count the finite
verbs in the narrowed text. This one has none. A span with no finite verb cannot
state a norm, so any `asserts` entry drafted for it is unanchored by construction
and no number of repair rounds will fix it.

Generalised: **repair-loop exhaustion on a short span is a scope conflict, not a
difficulty.** The two are indistinguishable from the findings log and opposite in
their remedy — one wants another attempt, the other wants the attempt abandoned
and the module written thin.

---

## L3 — "Regardless of scope, encode the example's lesson" is the same drift as P5's added body, arriving from the metadata side

**Ask: for each predicate in your module, can you point at the substring of the
NARROWED text that puts it there? Build the table before you validate, not after.**

P5 already warns about bodies that widen or narrow a rule. This clause shows the
same corruption entering through a different door: not from a body a translator
added, but from a **summary field the translator was told to satisfy**. The
instruction *"the one claim this module must express"* reads as a requirement, and
a conscientious translator will manufacture anchors to meet it.

The defence is the symbol-to-substring table (notes §4, P6). It is cheap, it is
mechanical, and it fails loudly: every symbol that cannot be pointed at a
substring is either an over-reach or a `NEEDS` borrow, and those two are the only
legitimate categories. On this node the table has four rows and every one of them
lands inside a nineteen-word line — which is what made the thinness of the module
defensible rather than lazy.

It also caught a live near-miss during drafting: `tiananmen_example` as the
constant's name. Fluent, obviously "correct" to anyone who has read the section,
and unanchored — the narrowed text names no event. A name is not exempt from the
table just because it is only a name.
