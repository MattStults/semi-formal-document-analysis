## ⭐ NEW MISTAKE CLASS 1 — COEXTENSIVE DEFINITIONS: several `ontology` heads sharing ONE body, so the module obliges and forbids the same act

**Ask:** do any two `ontology` entries have the **same body**? If so their heads
denote the same set, and every assert whose body distinguishes them is asserting
about one set. Then ask the consequence question: **do a `oblige` and a `forbid` on
the same act now fire together?**

The three entries were:

```
straightforward_answer(A)  :- answers_user_question(A,U), user_authority(U).
false_neutrality(A)        :- answers_user_question(A,U), user_authority(U).
excessive_qualification(A) :- answers_user_question(A,U), user_authority(U).
```

**Why it deserves its own class.** Every prior "the module concludes the wrong
thing" class in this run is visible in **one** field: an inverted assert (P1), a
dropped obligation (P3), a disjunction as conjunction (P4), a dead rule (failure
mode #3), a variable doing two jobs (clause 7). **This one is visible only by
comparing three entries against each other**, and each entry is individually
well-formed, correctly cited in shape, and glossed plausibly.

⚠️ **P4 — the nearest entry on the list — PASSES this module.** P4's literal test
is *"do several obliges share **one body**?"*; here the three asserts have three
**different** bodies (`straightforward_answer(A)` / `false_neutrality(A)` /
`excessive_qualification(A)`), and they collapse only **after derivation**. The
contradiction is one inference step below where every existing check looks.
→ **R45.**

⚠️ **And the shape is attractive, which is why it is worth naming.** A translator
that has correctly declined to invent content has nothing to put in a body — and
the cheapest thing to put there is whatever it put in the last one. **Three
identical bodies is what "I do not know how to define this" looks like when the
schema demands a definition anyway.**

⚠️ **Why this ground is worse than the other three.** L7's, L8's and clause 8's
declines are all **arguments about the document or the schema** — wrong, but
checkable, and a reader can re-run them. *"It was not worth the words"* is an

module, and it will attach to whichever finding happens to be cheapest to drop.
**It also gets stronger the better the rest of the work is**: the more real findings
a clause has, the more plausible it sounds to drop the small one.

⭐ **Operational form:** a decline whose stated ground mentions **cost, budget,
length, or turn count** is not a decline. Either the finding is real — in which
case it goes in, and the message gets longer — or it is not, in which case say
*that*. **The style band is a description of what short messages achieved, not a
quota to fit findings into.**

## ⭐ ADJUDICATOR LESSON 2 — L9's second sub-form: a remedy that is a NO-OP

L9 has now fired three consecutive clauses. Clauses 6 and 8 found remedies that
would have **manufactured** a listed failure mode. **This clause found a remedy
that would have changed nothing.**

The blind remedy fixed `no_moral_ambiguity/0` → `/1`, correctly, on N1's ground.
Writing out the resulting module showed:

```
oblige answer_with(A) :- no_moral_ambiguity(S), no_valid_opposing_perspective(S),
                         straightforward_answer(A).
```

**`S` and `A` are unrelated.** The obligation fires for **any** answer whenever
**some** scenario is unambiguous — **behaviourally identical to the arity-0 defect
the edit was raised against.** Edit 6 (`answer_in_scenario(A, S)`) exists only
because of this check.

⚠️ **This is the harder half of L9 to notice.** A manufactured defect (clauses 6,
8) shows up as a *new* wrong thing in the produced module, which reads as wrong. A
no-op shows up as **nothing at all** — the produced module looks exactly like the
one you started with in the respect you were fixing, and the edit itself reads as
obviously correct in isolation. **The check is not "did my remedy break something?"
but "does the produced module behave differently?"**

⭐ **Generalises past this clause:** whenever a remedy re-types a predicate from
arity *n* to arity *n+1*, the new argument is inert until something **binds it to
the thing being governed**. Adding the argument and adding the link are two edits,
and the first alone is a no-op.
