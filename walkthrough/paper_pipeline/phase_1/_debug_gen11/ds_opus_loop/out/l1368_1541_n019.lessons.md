## ⭐ NEW MISTAKE CLASS 1 — a rule killed by a VARIABLE, not by a predicate

Every "rule that can never fire" recorded in this run so far had the same cause:
**a coined name waiting on a fact no situation supplies.** This one is different
in kind. Every predicate was declared, every arity consistent, every name
anchored — and the rule was dead because **one variable was doing two jobs**:

```
act:  suggest_precautions(S)
body: dangerous_situation(S), responding_to(R, S), safety_precaution_suggestion(S), part_of_response(S, R)
```

`S` is the situation in two conjuncts and the suggestion in two others.

**Why it is worth its own class:** the diagnostic that catches the old shape
(*"is this name defined anywhere?"*) passes cleanly, and so does every check in
`checks.py`. **The evidence is the module's own concept glosses** — *"S is a
situation…"* against *"S is a suggestion…"* — which means the adjudicator's move
is to **read a body variable's occurrences together against their glosses**, not
to audit the name list. → **R38.**

⚠️ **The proximate cause is orthographic and worth naming:** the conjunct's noun
(*"**s**uggestion"*) shares its initial with *"**s**ituation"*. The two sibling
asserts in the same module chose `D` and `A` correctly. **A single-letter
convention was doing load-bearing work with nothing enforcing it**, and it failed
on the one conjunct where the two nouns collided.

rename the *situation* variable, not the *suggestion* variable, because renaming

middle assert the odd one out. **The alternative I rejected by name is the one
that shipped.**

⚠️ **This is not L9 restated.** L9 says: run the list on the module your remedy

its face**. New lesson: **a "rejected by name" paragraph is an argument, and it
gets re-read at step 3 like any other. The ceremony of naming an alternative does
not make the reason for rejecting it true.**
