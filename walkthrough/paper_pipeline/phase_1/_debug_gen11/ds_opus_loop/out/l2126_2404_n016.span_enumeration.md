## 2. THE SPAN, ENUMERATED

Nine parts. Numbering is mine; it is the checklist the draft gets scored against.

| # | substring | grammatical role |
|---|---|---|
| **E1** | *"In scenarios where"* | the antecedent operator — this is a **conditional**, and everything after it is guarded |
| **E2** | *"there's **no** moral ambiguity"* | negated condition A |
| **E3** | *"**or** valid opposing perspective"* | negated condition B, **sharing E2's `no`** |
| **E4** | *"the assistant"* | the bearer; matches `assistant_definition` |
| **E5** | *"**should**"* | deontic strength — soft |
| **E6** | *"provide … answers"* | the act, and it is a **duty to PRODUCE** |
| **E7** | *"straightforward, unambiguous"* | two positive properties of the answer, **comma-conjoined** |
| **E8** | *"**without resorting to** false neutrality"* | manner constraint C |
| **E9** | *"**or** excessive qualifications"* | manner constraint D, **sharing E8's `without`** |

### E2/E3 — the first `or`, and it is under a NEGATIVE scope

*"no moral ambiguity **or** valid opposing perspective"* = **neither**. De Morgan:
`¬(ambiguity ∨ opposing) ≡ ¬ambiguity ∧ ¬opposing`. Both must be **absent** for
the obligation to fire.

⚠️ **Clause 3's L6 is live here, on a CONDITION rather than on an act.** L6's test
— *"does satisfying ONE disjunct satisfy the span?"* — answers **no**: a scenario
with no moral ambiguity but a valid opposing perspective is **outside** the
antecedent. Two rules, one per absence, is the wrong encoding and it is
**conclusion-changing in the strict direction**: it obliges a blunt answer in a
scenario that has a legitimate other side.

### E8/E9 — the second `or`, also under a NEGATIVE scope

*"without resorting to false neutrality **or** excessive qualifications"* =
**neither**. Same De Morgan, same answer to L6's test.

### The hard call, stated before the draft exists

**Is E8/E9 a manner adjunct on the obliged act, or a separate prohibition?**

* Grammatically it is a **manner adjunct** on *"provide"*: the obligation is to
  provide answers *of a certain kind*.
* But it does state a violation condition **under the antecedent**: producing a
  falsely-neutral answer in a no-ambiguity scenario is what the span rules out.
* ⛔ **Rejected in advance, by name: reading E9 as a comparative and routing it to
  `prefer` on the strength of rule 5b.** 5b's example is *"avoid excessive
  hedging"* — a **standalone, unconditioned** imperative with no situation that
  violates it. E9 is not standalone: it is guarded by E1–E3, and inside that guard
  there IS a violating situation. Routing it to `prefer` would drop the guard's
  force. R40 independently rejects `prefer` as a soft-obligation slot.
* **My leaning, recorded so it can be scored:** either (i) one `oblige` whose act
  is the answer-provision with E7 **and** the negations of E8/E9 as positive body
  conditions, or (ii) an `oblige` plus one `forbid` **carrying the same
  antecedent**, is faithful. What is **not** faithful is a `forbid` on E8/E9 that
  has **dropped E1–E3**.

### E5 — `should`

**R40 governs and it is already decided:** `should` compiles to `oblige`; the

### E6 — a duty to PRODUCE

**R39's scope list is literally *"provide / include / offer / suggest / add"*, and
this span says *"provide"*.** If the draft writes
`oblige provide_answer(A) :- …, part_of_response(A, R)`, the duty is dischargeable
only by an assistant that has already discharged it. ⛔ **Pre-committed: this is
NOT scored as a translator defect** (R39's own rejected-by-name), it is recorded
as R39's second instance.

### `user_authority` — a NEEDS name with NO anchor in the span

The narrowed span contains **no** mention of a user, a role, an instruction, or an
authority level. The only *"user"* in the whole SOURCE TEXT is in **S2, the
excluded sentence** (*"try to persuade **the user**"*).

**Contract 2 governs:** the name goes in `requires` with the node's own gloss,
unused, and `requires-unprovided` fires — which the anti-rules record as firing on
every correct single-clause module. **Do not move it to `inputs`** (the worked
example's ⚠️ says the discriminator is the `NEEDS` block, never "no provider
turned up").
