### F1 — ⭐ THE `ontology` ENTRY IS A SELF-LOOP THAT DERIVES NOTHING, AND IT SILENCED A CHECK

```json
{ "atom": "underlying_prompts(P)", "body": "underlying_prompts(P)", ... }
```

Rendered, that is `underlying_prompts(P) :- underlying_prompts(P).` — failure

head*, so the name is not headless, so neither `concept-declared` nor
`situation-input` fires on it.

⚠️ **The general form, which I believe is new: a rule that derives nothing still
counts as a definition for the checker.** The dead rule did not merely fail to
help — it **bought silence**. And clingo ran on this module (the notes come from
`_check_clingo`'s output blob) and said nothing about the self-loop, because an
unfounded atom is not a warning.

⚠️ Also a category error on its own terms: a name cannot be both something this
module derives (`ontology`) and something supplied at query time (`inputs`).

**Remedy: delete the `ontology` entry; keep the name in `inputs`.** Whether a

and the span supplies no criterion for recognising one. `ontology` then becomes
