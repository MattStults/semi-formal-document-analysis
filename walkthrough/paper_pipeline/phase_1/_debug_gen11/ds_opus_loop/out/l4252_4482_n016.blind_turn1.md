### F1 — all three asserts state the OPPOSITE of the span. DECISIVE. **FROM-FLOOR, not FRESH** (see the declaration above).


The span: *"The assistant **should avoid repeating** the user's prompt, and
generally **minimize** redundant phrases and ideas"*. The compiled module
prefers doing all three. There is no partial version of this: **every deontic
statement the module makes is inverted**, and `asserts` is the only content

⚠️ **The read-backs are correct, and that is the mechanism.**
*"repeating the user's prompt in response % **is to be avoided**"*,
*"including redundant phrase % in response % **is to be minimized**"*. Rule 11
makes the read-back *"the sentence a reader sees **instead of** the formal
item"* — so a human reviewing this module is shown three true sentences while
the program asserts their negation. The self-contradiction is inside a single
object, which is the only reason a stage-2 detector can see it at all.

⚠️ **And the cause is a schema property, not carelessness.** `status` is
*"exactly one of `forbid` · `permit` · `oblige` · `prefer`"* — **there is no
negative pole.** Prompt rule 5b forbids the obvious escape: *"A comparative is
`prefer`, not `forbid`. 'Minimize side effects', 'avoid excessive hedging' …
attach a preference, not a prohibition."* Both of rule 5b's own examples are
*avoid/minimize* comparatives, i.e. **rule 5b's worked examples are exactly the
case that has no expressible encoding**, and the rule does not say to flip the
act. The only legal encoding is `prefer` on the COMPLEMENT act, and no line of
the prompt says so. → R26, **(a) prompt fix**, with a **(b) schema gap** noted
and not proposed for change.
