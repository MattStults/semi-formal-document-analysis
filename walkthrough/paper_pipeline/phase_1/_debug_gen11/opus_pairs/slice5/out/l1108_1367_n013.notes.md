## §1 ⭐ THE ABSTENTION ANSWER, IN WORDS

**I do not abstain, because the node establishes a structural fact about the DOCUMENT —
the heading's inline label `authority=user` — which the span states verbatim and which is
expressible as rules; the abstention triggers in `00_task.md` name kinds of passage that
supply no such fact, and the trigger that literally matches this span ("it is a section
heading") is one the production contract itself resolves against abstention for exactly
this sub-case.**

`00_task.md` states the triggers:

> If you cannot translate this clause faithfully — **it is a section heading**, it states a
> goal rather than a condition, it is an example, or its content is not expressible as
> rules — **abstain and give the reason**.

Each trigger, by name:

1. **"it is a section heading" — LITERALLY TRUE, and it does not carry.** My span is a
   `####` markdown heading; this is the first trigger named and I take it seriously rather
   than by reflex. What defeats it is `node_worked_example.md`, which contains a heading
   node (`l3995_4164_n001`) as one of the four GOOD examples and says of it in bold:
   > **This node obliges nobody, and it is still a translation, not an abstention.** There
   > are three routes: a node stating a norm goes to `asserts`; a node stating a
   > **structural fact** about the document — which authority a section carries, what class
   > a thing falls in — goes to `ontology` with `asserts` empty; only a node that
   > establishes *neither* is an abstention.

   and, decisively for the trigger-by-kind reading:
   > What decides between them is whether the node establishes anything the document says —
   > **not what KIND of passage it is.**

   The 00_task trigger list is prefixed *"If you cannot translate this clause faithfully"* —
   the list is a list of reasons faithfulness is unavailable, not a set of syntactic
   sufficient conditions. A heading whose only content is its title supplies nothing and
   triggers it. A heading carrying an inline metadata attribute supplies a document fact and
   does not. Mine is the second. The worked example is the same shape one level of authority
   over: same `####`, same imperative title, same `{#anchor authority=X}` block.

2. **"it states a goal rather than a condition" — NO.** `authority=user` is not a goal or
   an aspiration; it is a label assignment with a truth value, made by the document about
   itself. (The heading *title* is arguably goal-ish, but it is not what this node selects —
   see §3.)

3. **"it is an example" — NO.** No good/bad pair, no illustration, no dialog.

4. **"its content is not expressible as rules" — NO.** It is expressible, and the worked
   example shows the exact form: a heading constant, a `rule_under_heading/2` situation
   input, and an `ontology` entry deriving the authority predicate. Mine adds one ground
   document fact for the label itself.

**Does the heading STATE a norm or merely NAME a section? It names a section.** Grounds,
in order of weight: (i) it is a `####` heading, i.e. structurally a title — the section's
norms are stated in its body, which the graph carries as sibling nodes of the same span
(`l1108_1367_n014` is one); (ii) `ESTABLISHES` selects the authority claim and says nothing
normative, and under `PROVISIONAL.md` `ESTABLISHES` is a legitimate selector of *which*
claim; (iii) the title's own words could not be encoded faithfully anyway — five words that
never define "abuse", name no bearer and state no condition, so `forbid engage_in_abuse(A)`
would be failure mode ⑤ (hollow stub) and a direct breach of rule 5 ("do not write an opaque
symbol that echoes the document's words"). Its imperative FORM is the document's house
style for section titles ("Don't make unprompted personal comments" is the worked example's
heading, and that node encodes no prohibition either).

**Did the all-or-nothing shape of abstention influence the answer? It reinforced it; it did
not create it.** I reached "do not abstain" on the structural-fact route above, before
weighing the consequence. But the consequence is severe and worth recording as the finding
the task asks for: `10_output_format.md` requires that when abstaining I *"leave every list
empty"*, and `schema.py` enforces it — so there is no shape in which I abstain on the
heading and still record `authority=user`. Because the node's `PROVIDES` block hands me
`user_authority` and other nodes of this graph declare that name in their `requires`,
**abstaining would leave a name that other modules require undefined anywhere in the
graph**, and their bodies would wait forever on a definition no node supplies while looking
like they enforced something (failure mode ⑮, and the worked example's warning that
abstaining here "would strand every one of them"). Recording the consequence either way, as
asked:

* **translated (what I did):** `user_authority/1` is derivable; the cost is that the
  distribution over the section's rules is carried as an `assumed` fact rather than a
  textual one, and any reader who wants the strict text-only claim must read the licence.
* **abstained (rejected):** `user_authority/1` is defined nowhere; every consumer node's
  `requires` on it becomes a permanent dangling edge; and the document's own `authority=user`
  label, which is verbatim in the span, goes unrecorded by the corpus.

⚠️ **The shape I want flagged upward:** the all-or-nothing rule makes "this passage states
no norm" and "this passage states nothing" the same output. On heading nodes those are very
different, and the only reason this one did not collapse into an abstention is that a worked
example happened to cover the case explicitly. A translator without that example, reading
`00_task.md` alone, would abstain here and be following the instructions as written.

## §2 What `authority_convention.md` obliged me to do

The convention paragraph is mandatory for exactly this span class ("Headings in this
document carry inline `authority=X` labels … When you emit a node for such a heading"). It
obliged me to:

1. **Record the dependence on the document's authority-level definitions under a SHARED,
   document-wide canonical name**, one per level — here `user_authority` for the level and
   `authority_levels_hierarchy` where the ordering is at stake. The node handed me both
   (as `PROVIDES` and `NEEDS` respectively), so the obligation reduces to spelling them
   exactly as given and NOT re-deciding them: `user_authority` is the ontology head and its
   concept name, `authority_levels_hierarchy/2` is the sole `requires` entry.
2. **Never coin a per-section name for the dependency.** The forbidden patterns are
   `<section>_section_authority` / `<section>_section_root_authority`. I coined
   `avoid_abuse_heading/0` and `heading_authority/2`; **neither is a per-section authority
   coinage.** `avoid_abuse_heading` is a constant naming the document heading (an argument,
   never the authority concept) — it is what the convention's own golden shape uses the
   heading for; `heading_authority/2` is a document-WIDE relation between any heading and
   any level, not a name minted for this section. The failing ds3 shape would have been
   `avoid_abuse_section_authority(R)` as the head, and I did not write it.
3. It also settles a question I would otherwise have had to guess: the convention explicitly
   contemplates BOTH the `needs` form and the `provides` form as canonical ("needs OR
   provides — the shared NAME is what makes the edge class matchable"). So a heading node
   both *providing* the level name and *needing* the hierarchy — which is my exact shape —
   is the intended one, not a duplication to be cleaned up.

I did not read or run `smoke_authority.py`; the convention is "prepared, NOT yet run live",
