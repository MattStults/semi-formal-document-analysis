## C2 — Is a truncated/exemplified bound ILLUSTRATIVE or DEFINING? (and which way does the error run)

**Ask:** does the span bound an exception with a GENERAL TERM followed by an example — *"other
principles (such as X)"*, *"policies, e.g. Y"*? If so, does any assert body reference the EXAMPLE
rather than the general term? If it does, you have converted an open bound into a single-item
bound, and the exception now runs in every context that violates one of the principles you did not
name.

**Why it matters:** the error direction here is counter-intuitive and is the opposite of N4's.
N4's lesson is that propagating a qualifier invents a restriction while dropping it over-permits.
On an *exception's bound*, encoding the illustrative example is what over-permits — the example
makes the guard SMALLER, so more conduct escapes the prohibition. `such as` is illustrative by
definition in English; it never defines the term it follows. Adjacent to P5 and N4, but neither
covers a bound stated as `general term + instance`.

**Tag: MEASURED** here as a near-miss avoided; the pull toward encoding it was strong because the
NEEDS block supplied the example as a ready-made predicate.

**⭐ MECHANICALLY CHECKABLE — partially, as a FLAG not a verdict.** ~8 lines: regex the narrowed
text for `(such as|including|e\.g\.|for example)` within an `unless|except|provided|as long as`
clause; if it hits, assert that at least one assert `body` contains a predicate whose gloss uses
the GENERAL term's wording, and print for human review any assert body containing a NEEDS name
introduced only by that parenthetical. It cannot decide illustrative-vs-defining — that stays a
judgement — but it can guarantee the judgement was faced.

## C3 — A CONJUNCTIVE defeater needs ONE ASSERT PER CONJUNCT

**Ask:** count the conjuncts of the `unless` / `except when` / `provided that` clause (split on
`and`, on a comma series, and on stacked modifiers such as *"instructed to do so **in a context
that** …"*). Call it *k*. Now count the asserts that carry the same `status` and the same act
functor. If that count is 1 while *k* ≥ 2, the module is almost certainly leaning on the absence
of the whole conjunction — the N5/rule-4 defect — because `¬(a ∧ b)` has no single positive
ground.

**Why it matters:** `unless (a and b)` means the norm survives on *k* distinct positive grounds
(`¬a`, or `a ∧ ¬b`), and rule 4 requires each to be written separately with its own read-back. A
single assert can only express this by negating the conjunction, which is exactly what fails.
N5 says "make it positive" and N7 says "do not assert on the excepted branch"; neither tells you
how many asserts the UNEXCEPTED branch needs. This clause has *k* = 2 and 2 asserts.

**Tag: MEASURED** on this clause (as the shape that produced a correct module), **INFERRED** as a
general rule — I have one instance, not a failure to point at.

**⭐ MECHANICALLY CHECKABLE — yes, ~10 lines, as a warning.** Extract the substring after
`unless|except|provided that|as long as` from the narrowing; `k = 1 + n_of(" and ")` plus one per
`that (does not|is not)` relative clause; compare against
`Counter((a["status"], a["act"].split("(")[0]) for a in mod["asserts"])`. Warn when
`count < k`. False positives on genuinely single-conjunct defeaters worded with an `and` inside a
noun phrase, so it is a warning, not a gate.

## C4 — Was the HEDGE TIER of the modal recorded anywhere at all?

**Ask:** does the narrowed span use `should`/`should not`/`generally`/`typically`/`by default`
rather than `must`/`must not`/`never`/`always`? If so, `status` cannot carry the difference —
`forbid` from `should not` compiles byte-identically to `forbid` from `must not`. Does your NOTES
file contain an explicit sentence saying so, and does at least one `read_back` use the span's own
modal rather than an unhedged one?

**Why it matters:** P7 covers defeasibility whose remedy is "push it into a body". A modal TIER has
no body to be pushed into (this is the same gap N2 identified for matrix-verb hedges) and no
`toggleable` slot, so the only surviving trace is prose. Without a rule forcing it, the hedge
vanishes silently and the corpus cannot later distinguish a hard prohibition from a soft one —
which is precisely the distinction an authority-tier analysis needs.

**Tag: MEASURED** — the loss is real and unfixable at this schema; I recorded it in four places on
this clause because the schema offers no fifth.

**⭐ MECHANICALLY CHECKABLE — yes, and this one can be a hard gate.** ~6 lines:
`hedged = re.search(r'\b(should|generally|typically|by default|ordinarily)\b', narrowed)`; if
`hedged` and the module has any `asserts`, require that at least one of its `read_back` strings
contains the matched modal, **and** that the notes file matches `r'(should|hedg).{0,120}(must|not
encodable|no hedged pole)'`. Both halves are pure string tests over artifacts already on disk, and
the first half alone would have caught a module that silently upgraded `should not` to a bare
prohibition in its read-back.
