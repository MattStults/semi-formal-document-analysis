## L1 — Is the phrase you are encoding inside a **BAD** arm?
**MEASURED — a live near-miss on this clause, caught at Turn 3/N6.**
This span's BAD response contains *"even if they're public figures"*. Read as
document text, that is a textbook N6 trigger — a span excluding an exception,
whose destination is `forbid_body` as `{ head: permit, banned: public_figure }`.
It is the exact opposite of what the span teaches: the whole example exists to
say the public-office route **is** available. A negatively-marked arm is text the
document is quoting in order to reject, and every existing entry (N6, P5, N10)
reads span text without asking which arm it came from — N10 in particular would
**pass** a symbol anchored to a BAD-arm substring, because the substring is
genuinely there.
**Ask:** for every phrase you drew content from, which `<assistant>` arm is it
inside? If it is inside an arm marked `<!-- BAD… -->`, you may use it only to
describe what the document rejects — never as the ground of an `ontology` entry,
a `forbid_body` entry, or an assertion body.
⭐ **MECHANICALLY CHECKABLE — yes, a few lines.** Split the span on
`<assistant>`; collect the text of arms whose comment matches `BAD`; for each
coined predicate name, split on `_` and test whether its content words occur in
the BAD-arm text and *nowhere else* in the span. Flag on hit. Cheap, no model
call; false positives are cheap to dismiss and the failure it catches is silent.

## L2 — On a span with no deontic verb, what supplies the force?
**MEASURED on this clause (judgement call J1, unresolved).**
The span contains not one of *must / should / may / never / required*. Its
verbs are `can't provide`, `can provide`, `meant`, `want`. All the deontic force
in the module — an `oblige` and a `forbid` — is read off the GOOD/BAD markers
and off `ESTABLISHES`'s paraphrase (*"should provide"*). That reading may be
right, but it is an inference and it is currently invisible: an `oblige` derived
this way is byte-identical to one lifted from a *"must"*. This is P7's problem
(*"an unconditional oblige is byte-identical to one whose default was dropped"*)
one level up — here it is not a dropped hedge but an **absent modal**.
**Ask:** does the narrowed span contain a deontic modal at all? If it does not,
and your module emits `oblige` or `forbid`, name in your notes what supplies the
force — the GOOD/BAD marking, `ESTABLISHES`, or an inference — and say what the
weaker status would have been.
⭐ **MECHANICALLY CHECKABLE — yes, and it is the strongest candidate here.**
`re.search(r"\b(must|should|shall|may not|never|required|prohibited|do not|don't)\b", span, re.I)`;
if no hit and any assert has status `oblige`/`forbid`, require the notes file to
contain a marked line (e.g. `FORCE-SOURCE:`). Two conditions, both textual, no
judgement in the check itself.

## L3 — If the span has a BAD arm, which assertion does the BAD response violate?
**MEASURED on this clause (judgement call J3).**
P10 asks whether the two arms **differ**, which presumes both got encoded. It has
nothing to ask of the shape this module actually took: the BAD arm has no item
of its own and is discriminated only by *failing* the obligation the GOOD arm
establishes. That may be correct — giving it its own `forbid` double-encodes A1's
contradictory — but on this route nothing checks that the BAD response is
discriminated **at all**, and a module that silently drops the negative pole
looks exactly the same.
**Ask:** if the span has a BAD arm and your module gives it no assertion of its
own, name the assertion the BAD response violates and the body literal that
fails on it. If you cannot name one, the negative pole has been dropped.
⭐ **MECHANICALLY CHECKABLE — partly, and only as a presence check.** Detect
`BAD` in the span, then require the notes to carry a named `BAD-VIOLATES:` line.
Whether the named assertion really is violated needs a solver run against a
constructed situation, which is a stage further than a few lines of Python.

## L4 — Does every arity-≥2 **input** gloss fix its argument order?
**INFERRED (extends N8, which is MEASURED, from `requires` to `inputs`).**
N8 is scoped to *borrowed* relations, on the ground that a provider mismatch is
silent. The identical inversion is available on a module's own `inputs`: this
module writes `public_office_contact_info(C, P)` and `private_contact_info(C, P)`
with the information first and the person second, and nothing but the gloss says
so — a test-case author who supplies `(P, C)` gets a program that grounds, runs,
and answers wrongly with no error anywhere. On this clause N8 could not fire at
all, because both borrowed names are arity 1; the exposure was entirely on the
self-coined side.
**Ask:** for each `inputs` entry of arity ≥ 2, does its `concepts` gloss say
which argument is which?
⭐ **MECHANICALLY CHECKABLE — yes, a few lines.** For every `inputs` entry whose
arity ≥ 2, look up its concept gloss and require an ordering marker
(`first argument`, `second argument`, or the argument variables named in order).
Purely structural.

## L6 — Did pushing a hedge into a body make the rule fire only after the act it recommends?
**INFERRED (avoided, not committed, on this clause — judgement call J4).**
P7 says to push a hedge into a body where you can. This span's hedge is *"If you
want, I can provide…"*, and the obedient application of P7 produces
`requester_wants(A)` in the body of the very rule that recommends making the
offer — so the rule fires only in situations where the user has already agreed
to a thing not yet offered. Result: a rule that looks like an encoded default
and can essentially never fire (failure mode ③/3), reached by following the
review list rather than by ignoring it. This is a concrete instance of the
standing warning that an entry's ASK and its REMEDY have different validity
ranges.
**Ask:** for each hedge you pushed into a body — could the body condition
become true *before* the act the assertion governs? If it can only become true
after, the remedy has produced a dead rule; carry the hedge in the `prefer`
status and record it in the notes instead.
⭐ **MECHANICALLY CHECKABLE — no.** The temporal relation between a body
condition and its act is not recoverable from the text of either. A weak proxy
exists (flag a body literal whose predicate name shares a stem with the act
term), and I would not trust it.
