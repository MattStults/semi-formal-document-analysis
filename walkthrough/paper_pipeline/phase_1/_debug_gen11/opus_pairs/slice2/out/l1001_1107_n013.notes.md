### (c) What `ESTABLISHES` demands, and the diff in BOTH directions (N3)

`ESTABLISHES` asks for three propositions:

* **E1** when asked for Acme employee information, the assistant must not share people's
  home addresses, phone numbers, SSNs, or credit card details → **= S4 + S2**
* **E2** even if they have leaked online → **= S3**

**ESTABLISHES → span (does it ADD?)** No. All three are anchored in the span, E1 and E3
verbatim in the GOOD reply, E2 verbatim in the GOOD comment. It does perform one
transformation: it reads a first-person assistant *utterance* (*"I can't help share…"*) as
a *norm* (*"the assistant must not share…"*). That transformation is licensed by the GOOD
label, which is the document endorsing the utterance, not merely printing it.

**Span → ESTABLISHES (does it DROP?)** Yes, two propositions: **S6** (bare refusal is BAD
on chain-of-command grounds) and **S7** (assembling the data by scraping is BAD).

Under `PROVISIONAL.md`, `ESTABLISHES` *may* select **which** claim the module expresses; it
may not add content or drop a qualifier attached to the claim it selects. It drops no
qualifier of E1–E3 (in particular it keeps *"even if they have leaked online"*, which is
the qualifier that matters). So the drops are legitimate **selection**, and I encode E1–E3.

Two deliberate consequences, recorded rather than silently taken:

* **S6 is in fact partly carried.** The preference assert requires *both*
  `declines_to_share_private_details(R)` **and** `privacy_safe_alternative(R)`. The bare

  clause's rule" failure (`00_task.md` rule 1). **This is a known, deliberate
  under-assertion, and it is the single thing in this module I would most want a reviewer

## ⭐ Stage 0b — THE ABSTENTION QUESTION, answered in words

**The question:** the span is headed `**Example**: asking for Acme employee information`,
the node's `kind` is `meta`, and `00_task.md` line 112 lists *"it is an example"* as an
abstention trigger, in the same breath as a section heading. Should this clause have been
translated at all?

**My answer: NO, do not abstain — translate.** At length, because this clause is the
direct test of it:

1. **The prompt contains two rules on this point and they contradict each other.**
   `00_task.md` line 112 makes "it is an example" a *sufficient* trigger to abstain.
   `node_worked_example.md` line 213 is a whole worked example titled *"A worked-example
   node — translate the lesson, not the dialog"*, which takes a document GOOD/BAD response
   pair and **translates it** as a `prefer`. Line 296 of the same file states the
   discriminator outright: *"What decides between them is whether the node establishes
   anything the document says — **not what KIND of passage it is**."* Those two sentences
   cannot both be applied. This is filed as a PROMPT DEFECT in
   `l1001_1107_n013.prompt_finding.md`, because it is a defect in the contract and not in
   this module, and the two files disagree in the direction that decides an abstention.

2. **Given the contradiction, I follow the more specific and later instruction.**
   `node_worked_example.md` is the file written *for the node shape I was actually handed*
   (`ESTABLISHES`/`NEEDS`/`PROVIDES`), it addresses the GOOD/BAD-example case by name, and
   it states its rule as an explicit discriminator rather than as an item in a list. It is
   also the later of the two in the concatenated system block. `00_task.md`'s list reads,
   in context, as a list of *symptoms* of untranslatability, and line 296 supplies the
   underlying test the list is a proxy for.

3. **Applying that test, this node passes it.** The span establishes things the document
   says, and they are not recoverable from the general privacy rule alone:
   * the **extension** — that home addresses, phone numbers, SSNs and credit card details
     are the private personal information at issue (and, pointedly, that emails are not on
     the refusal list even though the user asked for them);
   * the **excluded exception** — that leaking online does not license sharing;
   * the **shape of the right response** — declining *and* offering a privacy-safe route,
     as against a bare refusal that the document separately marks BAD.
   A module that recorded none of this would strand content the document does state.

4. **The honest alternative was considered and rejected by name.** The alternative is:
   *"the document's own voice here contains two finite verbs inside an HTML comment; the
   normative content belongs to `privacy_protection_rule`, which another node owns; this
   node displays a dialog and therefore states nothing of its own — abstain."* I reject it
   because the GOOD/BAD labels **are** the document asserting something, and because the
   four categories, the leaked-online exclusion, and the alternative-path preference are
   content the general rule does not carry. But I record it because it is not a silly
   position, and the abstention rate is a signal the project wants: if the owner rules
   that `00_task.md` line 112 governs, this module should be replaced by an abstention
   object and **nothing else about it needs re-deriving**.

5. **What would have made me abstain.** If the span had been the heading line alone, or if
   the GOOD/BAD comments had been absent (leaving three unlabelled replies with no verdict
   in the document's voice), I would have abstained: there would then be no proposition in
   the document's own voice to translate, and every rule I wrote would be my reading of a
   dialog rather than the document's claim.

**The word "abstain" appears in this transcript deliberately and the question was asked
before the first draft, not after it.**

## UNSUREs I could not settle

1. **`publicly_leaked/1` is declared in `concepts` but in neither `inputs` nor `ontology`.**
   It is used only as the `banned` slot of the `forbid_body` entry. Putting it in `inputs`
   would be defensible (it *is* a case-side fact) but would create precisely the
   "coined name that appears in no body" fingerprint P9 hunts for — and it can never
   appear in a body, since the `forbid_body` entry's whole content is that no rule may
   condition on it. `schema.py` does not require a declaration site for a `forbid_body`
   name and deliberately does not check that a concept is used. I left it in `concepts`
   only. **Unsettled: whether the schema should require `forbid_body` names to be
   declared, and if so where.**

2. **`share` closure = `cepa` vs `unclear`.** N7 warns that a `cepa` closure can re-assert
   a silence you just declined to assert. I chose `cepa` on positive textual grounds — the
   approved reply itself goes on to share other material with the same requester, so the
   span exhibits permitted sharing rather than merely failing to forbid it. `unclear` (an
   example settles nothing general) is the live alternative and I would not fight hard for
   `cepa`.

3. **`request_for_private_information/1` licensed `textual`.** The phrase does not occur as
   a substring (N10); what occurs is the request itself, printed verbatim in the `<user>`
   turn. I read a displayed message as span text and kept `textual`. If the ruling is that
   only the document's *own voice* can support a `textual` licence, this and several other
   concepts drop to `assumed` — and so, note, does the entire module, since every one of
   its facts is drawn from the displayed messages or their labels.

4. **S7 (the scraping arm) is unencoded** — see Stage 0 (c). Deliberate, not an oversight.
