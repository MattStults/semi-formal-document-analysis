# PROMPT DEFECTS found while translating `l1108_1367_n010`

⭐ Filed because I **declined a change the review lens would otherwise demand** — or made one the
prompt's own worked examples contradict. Per the drafter brief, this is **not** "the module is
clean": the module is clean *because* I followed the prompt's stated rule over the prompt's
demonstrated example, and a translator who follows the example instead will produce the defect.

Both findings are in the **same file and the same failure class**: a worked example that
manufactures a `textual` citation for content its span does not state, in direct contradiction of
a rule stated in bold a few screens earlier in the identical prompt. The class the previous loop
named — *"licence inheritance: mechanically checkable; nothing checks it"* — is not merely
unchecked here. **It is taught.**

## PF-1 — the worked heading node marks a derived conclusion `textual` when its own derivation contains an `assumed` fact

**File:** `resolve_runs/graph_v2/node_worked_example.md`, **lines 197–201** (the `ontology` block
of the worked node `l3995_4164_n001`; the `assumed` concept it depends on is at lines 188–192).
Reaching me concatenated into `system_block.txt` at lines 479–484 / 470–474.
**Rule it contradicts:** `prompt/00_task.md`, the "A conclusion inherits the weakest licence in its
derivation" paragraph (system block lines 31–33).

The rule, `prompt/00_task.md` (system block lines 31–33):

> **Note: A conclusion inherits the weakest licence in its derivation.** If a rule depends on one
> `world` fact, everything it concludes rests on that fact.

The example, `l3995_4164_n001` (system block lines 470–484), in one module:

```json
{ "name": "rule_under_heading", "arity": 2, …
  "licence": "assumed", "cites": null,
  "inference": "the node speaks of the rules under a heading, so a relation between a rule and a heading must exist" }
…
{ "atom": "guideline_authority(R)",
  "body": "rule_under_heading(R, unprompted_personal_comments_heading)",
  "licence": "textual", "cites": "l3995_4164_n001", "inference": null }
```

The conclusion `guideline_authority(R)` is derived **through** `rule_under_heading/2`, which the
same module marks `assumed`. Weakest licence in the derivation is `assumed`; the conclusion is
marked `textual`. The example violates the rule.

It is worse than a bookkeeping slip, because of *what* the assumed step is. The step is the
propagation of a heading's inline `authority=` label to **every rule in the section it opens** —
the entire content of the node. Marked `textual`, the module tells a downstream reviewer that the
document *says* the label governs the section's rules. The document says no such thing on that
line; it prints an attribute. Failure mode 16 then applies exactly: *"A fact marked `assumed` with
its inference named can be checked. The same fact marked `textual` cannot."*

**What I did:** followed the rule, not the example. My `system_authority(R) :- …` ontology entry
is `assumed`, `cites: null`, with the inference naming the markup convention as the source. I
additionally split off the part that *is* textual — `heading_authority_label(no_erotica_or_gore_heading,
system)`, the label fact itself — so nothing textual was lost by the demotion.

**Why this is a defect and not my misreading:** the two heading nodes are structurally identical
(inline authority label, section-scoped propagation, `rule_under_heading` as the bridge). Any
translator pattern-matching my span to the worked example — which the prompt invites, since it is
the *only* heading-authority example given — emits the stronger licence. This is a defect that
propagates by imitation across the whole heading-authority edge class, which
`authority_convention.md` measures at **~47% of all golden-vs-ds3 edge divergence**. It is the
single largest node class in the corpus with a prompt-taught licence error.

**Suggested fix (one word plus one field, no restructuring):** in
`resolve_runs/graph_v2/node_worked_example.md` line 201, change that ontology entry to `"licence": "assumed", "cites": null,
"inference": "the heading's inline authority label is attached to the heading line; that it
governs every rule in the section the heading opens is the document's markup convention"`. Then
add one sentence beneath the example's "Things to notice" list: *"Notice the licence. The
conclusion is `assumed`, not `textual`, because `rule_under_heading` is `assumed` — a conclusion
inherits the weakest licence in its derivation, and a heading node is the commonest place that
rule is broken."*

## PF-2 — the worked conditional node marks a borrowed `NEEDS` concept `textual` and cites its own node for content the span does not state

**File:** `resolve_runs/graph_v2/node_worked_example.md`, **lines 47–49** (the
`authority_levels_hierarchy` concept of worked node `l527_796_n012`); system block lines 329–331.
**Rule it contradicts:** `prompt/00_task.md`, the "Do not manufacture a citation" paragraph
(system block lines 26–29).

The rule (`prompt/00_task.md`, system block lines 26–29):

> **Do not manufacture a citation to make a fact look textual.** Citing a plausible-looking clause
> for something the clause does not actually say is the single worst failure available here …
> An honest `assumed` is always better than a dressed-up `textual`.

The example:

```json
{ "name": "authority_levels_hierarchy", "arity": 2,
  "gloss": "which of two levels of the chain of command is the higher one",
  "licence": "textual", "cites": "l527_796_n012", "inference": null, "toggleable": false }
```

`l527_796_n012`'s span is *"These implicit biases are subtle and serve as defaults only --- they
must never override explicit or implicit instructions provided by higher levels of the chain of
command."* That span states **no ranking of levels**. It presupposes one. And the prompt itself
classifies `authority_levels_hierarchy` as a `NEEDS` name — i.e. *"established by OTHER nodes of
the graph"*, stated in the node input as *"never in `ontology`, never defined here"*. A `NEEDS`
name is by definition content this node does not state, so a `textual` licence citing this node is
contradictory on the prompt's own terms.

Note the example is internally inconsistent in a revealing way: in the very same `concepts` list,
`defaults_level/0` and `instruction_level/2` — also presupposed rather than stated — are correctly
marked `assumed` with inferences named. Only the borrowed name got the manufactured citation.

**What I did:** marked my `authority_levels_hierarchy/2` concept `assumed`, `cites: null`, with
the inference *"the ranking of authority levels is established by another node and handed to this
one in its NEEDS block; the narrowed heading line states no ordering at all."*

**Why it matters here specifically:** `prompt/10_output_format.md` **line 66** forces a `concepts`
entry for every `requires` entry (system block line 188, *"every `requires` entry must also have a
`concepts` entry saying what you need it to MEAN"*). So every node with a non-empty `NEEDS` must
write a gloss for content it does not state — the borrowed-gloss situation is **universal**, not
occasional, and the only worked example of it teaches the dressed-up `textual`. The prompt thereby
guarantees a manufactured citation on every node that follows its example, and the corpus's
commonest borrowed name is precisely this one.

**Suggested fix:** change that example entry to `assumed` with an inference such as *"the ranking
is established by another node and handed to this one in the NEEDS block; this span presupposes it
without stating it"*, and add one line to the "Three contracts the node shape adds" block (system
block lines 300–302), after contract 2: *"A `NEEDS` gloss records content another node states, so
it is `assumed` with the inference naming the NEEDS block — never `textual` cited to your own
node, which would be a manufactured citation."* (That contracts block is
`resolve_runs/graph_v2/node_worked_example.md` lines 11–21; the new line goes after line 19.)

## Cross-cutting note for the coordinator

PF-1 and PF-2 have the same mechanical signature and it is cheap to sweep the whole cohort for:

> a `concepts` or `ontology` entry marked `licence: "textual"` whose `name` appears in the node's
> `NEEDS` block, **or** whose `body` references any predicate declared `assumed` in the same
> module.

That is a few lines of Python over the module JSON plus the node's `NEEDS` list, and it flags both
defects without any judgment call. See `l1108_1367_n010.lessons.md`, entries L1 and L2 — filed
there as candidate REVIEW_LIST entries in question form.
