## L1 — Does any `textual` fact sit downstream of an `assumed` one?  ⭐ MECHANICALLY CHECKABLE

`l3995_4164_n001` derives `guideline_authority(R)` through `rule_under_heading/2`, marks that
bridge `assumed`, and marks the conclusion `textual` — in one module, contradicting
`00_task.md`'s *"a conclusion inherits the weakest licence in its derivation"* stated bold a few
screens earlier. Every heading-authority node that pattern-matches the example inherits the error,
and `authority_convention.md` puts that class at **~47% of all golden-vs-ds3 edge divergence**.

**Ask:** for every `ontology` entry with a non-null `body`, is any predicate named in that body
declared `assumed` or `world` — in this module's `concepts`, or by being a `requires`/`inputs`

citation to text that does not state the step.

**Check (over module JSON alone):** build `weak = {c.name for c in concepts if c.licence !=
"textual"}`; for each ontology entry with a body, split the body on `,`, take each literal's
functor, and flag the entry if `licence == "textual"` and any functor is in `weak`. ~10 lines. No
span text needed, which is why it is worth having: it fires with zero judgment.

**Duplicates?** Nothing in the list. The nearest is **P8** (tautology / gloss quality), which is
about a *rule's shape*, not its licence. The list currently has **no licence entry at all** — the

## L2 — Is any `NEEDS` name marked `textual` and cited to your own node?  ⭐ MECHANICALLY CHECKABLE
**MEASURED** — the prompt's worked node `l527_796_n012` marks its borrowed
`authority_levels_hierarchy` concept `"licence": "textual", "cites": "l527_796_n012"` for a span
that states no ordering. A `NEEDS` name is *by definition* content another node states
(*"established by OTHER nodes of the graph … never defined here"*), so `textual` cited to your own
node is self-contradictory on the prompt's own terms — and it is `00_task.md`'s named worst
failure, the manufactured citation.

This one is **structural, not occasional**: `10_output_format.md` line 66 forces a `concepts`
entry for *every* `requires` entry, so every node with a non-empty `NEEDS` must gloss content it
does not state. The situation is universal and the only worked example of it teaches the wrong
licence.

**Ask:** for each name in the node's `NEEDS` block, is its `concepts` entry `assumed` with an
inference naming the NEEDS block — or is it `textual` citing this node for content the narrowed
span never states?

**Check:** parse the `NEEDS:` names out of `prompt_user.txt`; for each, find the `concepts` entry
with that `name`; flag if `licence == "textual"`. ~8 lines. **Zero false positives are possible**
in the direction that matters: a genuine `NEEDS` name is never stated by the borrowing node's own
span, or it would not be a `NEEDS`.

**Duplicates?** Partially overlaps **N8**, which is about the *argument order* inside a borrowed
gloss. Same target (borrowed relations), different defect (licence, not order). Recommend filing
alongside N8 and cross-referencing; do not merge — N8's remedy is "write the order into the
gloss", L2's is "demote the licence", and a module can pass one while failing the other. This
module was drafted to pass both.

## L3 — On a heading node, was the abstention trigger ANSWERED in the notes, in words?
**MEASURED** as the previous cohort's single biggest gap (a silent answer counting as unasked),
and live here: `00_task.md`'s **first** abstention trigger is literally *"it is a section
heading"*, while the prompt's own heading worked example says a heading node is a **translation**,
not an abstention. A translator meeting a heading span faces two prompt passages pointing opposite
ways and can satisfy the checks under either without ever saying which it chose or why.

**Ask:** does the span match a listed abstention trigger (section heading / goal without a trigger
/ example / not expressible)? If yes, do the notes contain an explicit sentence answering *should
this have been translated at all*, with grounds — and, when `PROVIDES` is non-empty, does it say
that abstaining would strand the nodes waiting on that name?

**⭐ MECHANICALLY CHECKABLE — partly, and the partial check is the useful one.** Detecting the
trigger is mechanical (`span.lstrip().startswith("#")`, or `"authority=" in span`). Detecting
whether the notes *answered* is a substring search for the word "abstain" in the notes file —
cheap, and it catches the silent case, which is the measured failure. Judging the quality of the
answer is not mechanical and should not be attempted.

**Duplicates?** Nothing in the list — the REVIEW_LIST has **no abstention entry**, though the
route decision (assert / ontology-only / abstain) is the single largest branch a node module can
take. Note it should be phrased as "was it answered", never "should it have abstained": an entry
that presumes an answer would fire on every correct heading node, which is the P9 mistake the list
already had to correct once.

## L4 — Does the module encode the heading's own normative text as well as its authority label?
**MEASURED here as a near-miss I had to argue myself out of**, not as an emitted defect. This
span's heading text (*"Don't respond with erotica or gore"*) is a fluent, correctly-scoped
prohibition, obviously true of the section, and traceable to a substring — so it passes N10, P6
and a paraphrase check by construction. It is nonetheless another node's content: the section body
states the same rule, and `00_task.md` forbids folding another clause's content in. Encoding it
duplicates a `forbid` in the corpus under two citations, and **a duplicated prohibition is
invisible in every downstream check** — nothing counts how many nodes forbid the same act.

**Ask:** if the span is a heading, does `asserts` contain a norm drawn from the heading TEXT rather
than from its attribute block? If `ESTABLISHES` names only the authority assignment and `PROVIDES`
names only an authority predicate, the norm belongs to the section's own nodes.

**⭐ MECHANICALLY CHECKABLE:** flag any module whose span is a heading line
(`span.lstrip().startswith("#")`), whose `ESTABLISHES` contains "authority", and whose `asserts`
is non-empty. Three conditions, all string tests. Expected hit rate near zero on correct work,
which is what makes it a good gate rather than a P9-shaped nuisance.

**Duplicates?** Related to **N2** (a span *about* a rule does not state one) but distinct and, I
think, the more common heading case: N2's span is prose with a matrix verb, mine has no finite
verb at all. Also adjacent to **P6** (content outside the narrowing) — but here the content is
squarely *inside* the narrowing and still not this node's to state, which is exactly why P6 does

## L5 — Is a document-level fact written as a ground atom, and a rule-level one as a bodied rule?
**INFERRED** from applying N1 to a heading node (not independently measured here — I avoided the
defect at draft time rather than committing it).

N1 tells you to prefer a bodied rule over a coined constant, *and* reserves ground atoms for facts
about the document. A heading-authority node contains **one of each**, and getting them the wrong
way round is silent both ways: `system_authority(no_erotica_or_gore)` as a ground atom is inert —
no situation fact ever unifies with it, and every consumer of the `PROVIDES` name receives a
predicate that never matches — while writing the label fact with a body invents a condition the
markup does not have.

**Ask:** for each `ontology` entry, does its atom describe the DOCUMENT (a heading, a section, a
label) or a thing IN A JUDGED SITUATION (a rule, a message, a response)? Document facts take
ground atoms; situation-matching predicates take bodies. In particular: does every `PROVIDES` name
appear as the head of a **bodied** entry?

**⭐ MECHANICALLY CHECKABLE — the high-value half of it is.** Extract the `PROVIDES` names from
`prompt_user.txt`; flag any that appears as the head functor of an ontology entry whose `body` is
`null` and whose arguments are all constants. That is the inert-provider case, and it strands
every consumer node. The document-vs-situation judgment on other atoms is not mechanical.

**Duplicates?** A **narrowing of N1**, tightened to the `PROVIDES` case. N1 is flagged as the
list's highest-value entry and asks the right question, but it is answered by judgment; this
sub-case can be gated. Recommend appending to N1 rather than filing separately.
