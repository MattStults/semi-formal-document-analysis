## Q0 — SHOULD THIS HAVE BEEN TRANSLATED AT ALL?

**Answer: yes — translating was correct, and abstention would have been the worse error. But the
prompt genuinely contradicts itself on this point, and that contradiction is the highest-value
finding on this clause. It is conclusion-changing for the PROMPT, not for the module.**

### The case for abstaining

It is real and it is not weak.

1. `00_task.md` (system_block L109–114) lists four abstention triggers and the third is verbatim
   **"it is an example"**. This span is headed `**Example**: asking for Acme employee information`
   and the corpus record gives its `kind` as `meta`. On a literal reading of that sentence, this is
   an open-and-shut abstention.
2. `response_schema.json`'s own root description repeats it independently: *"A clause that cannot be
   translated faithfully — a heading, a goal with no trigger, **an example** — should be declined
   with a reason."* So the trigger appears twice, in two separately-authored artifacts.
3. The structural argument is the strongest one: **an example demonstrates a norm stated elsewhere;
   it does not state one.** The module's own `requires` is the confession —
   `privacy_protection_rule` is *"the rule that the assistant must not respond to requests for
   private or sensitive information about people"*, i.e. the norm this example illustrates, owned by
   **another node**. If the norm lives elsewhere, what is left here is an illustration, and
   `assert 1` (`forbid share(D) :- private_personal_information(D)`) is arguably this module
   re-stating the borrowed node's rule in its own voice — which contract at system_block L6–8
   forbids: *"Other clauses become `requires` entries, never copied rules."* That is the sharpest
   version of the abstain case and I want it on the record.
4. `kind: meta` is a corpus-level signal that this node is about the document rather than a norm of
   the document.

### The case for translating — which I find decisive

1. **`node_worked_example.md` contains a worked example that translates a document good/bad pair,
   and it is presented as one of the four GOOD ones.** System_block L495–548: node
   `l4251_4571_n029` is described in the prompt's own words as *"a document example (a good/bad
   response pair)"*, and the prompt's instruction is its heading: **"A worked-example node —
   translate the lesson, not the dialog."** It emits `outcome: "translated"` with one `prefer`
   assert. A translator that abstained here would be contradicting a labelled-good worked example.
2. **The prompt then states the discriminator outright, and it is not "what kind of passage is
   this".** System_block L574–579: *"Many graph nodes are commentary, headings, or document
   examples. The two honest answers are a small module that records only what the node actually
   establishes … and a clean abstention … **What decides between them is whether the node
   establishes anything the document says — not what KIND of passage it is.**"* That sentence is a
   direct denial of the flat "it is an example" trigger.
3. **The span contains document-voice normative content, not only dialog.** This is the substantive
   reason. The `<!-- GOOD: does not include SSNs, credit card info, and other private information,
   even if they've leaked online -->` comment is **not** an assistant utterance; it is the Model
   Spec's own editorial annotation adjudicating the arm. Same for `<!-- BAD[#chain_of_command] -->`
   and `<!-- BAD -->`. Three verdicts, in the document's voice, over three concrete responses. A
   corpus whose purpose is "which clauses bear on this behaviour" would be strictly worse off with
   those three verdicts absent. N2's matrix-verb test also passes on the annotation: the subject of
   *"does not include … even if they've leaked online"* is the assistant's reply, not OpenAI.
4. The `even if they've leaked online` qualifier is **content the general privacy rule may well not
   carry**. If this node abstains, the anti-exception disappears from the corpus unless some other
   node happens to state it. Abstaining here is a live content-deletion risk, not a neutral act.
5. `REVIEW_LIST` P10 exists at all — *"if the span is a GOOD/BAD pair, do the two arms differ…"* —
   which presupposes that GOOD/BAD example spans get translated. A review entry measured on a
   production module is evidence about what the pipeline does.

### Do `00_task.md` and `node_worked_example.md` agree?

**No. They contradict each other, and the contradiction is not reconcilable by reading alone.**
`00_task.md` L111 makes "it is an example" a *sufficient* trigger, in a bare list of four
categories. `node_worked_example.md` L574–579 says the category is *explicitly not* the test and
supplies a different test ("does the node establish anything the document says"), then demonstrates
the translate side on a good/bad example node. There is a charitable reading — L110–111 reads *"If
you cannot translate this clause faithfully — it is a section heading, … it is an example, …"*, so
the four could be read as instances of unfaithfulness rather than independent triggers — but that
reading requires the reader to demote a list item into an illustration, and the previous cohort's
measured failure (a span headed `**Example:**` translated with the word "abstain" appearing zero
times in the transcript) shows the list is being read as triggers-or-ignored, not as illustrations.
Filed under PROMPT FINDINGS.

### Verdict

Translate. The module's `outcome: "translated"` is **correct**. Abstention would have deleted three
document-voice verdicts and the "even if leaked" anti-exception from the corpus.

**Is this conclusion-changing?** For the module: **no** — Q0 does not change the outcome field.
For the prompt: **yes** — see PROMPT FINDINGS 1. And note the abstain case's point 3 (copied rule
vs. borrowed rule) is NOT fully answered by this verdict; it is the honest residue, and it is what
makes the licence question in the Licence Audit live rather than cosmetic.

### Both BAD arms — P10 and P3

**P10, literally applied, passes.** The GOOD arm gets `prefer respond_with(R)`; neither BAD arm gets
any status. The two poles are therefore not byte-identical and the compiled program can tell them
apart — this is not the measured failure P10 records. I want to be precise that the module does
**not** commit that error.

**But P10 passes vacuously, and P3 fires.** P3's fingerprint is *"a claim present in `claims` and
encoded nowhere"*; the shape here is one degree worse — **S5 is present in the SPAN and appears in
neither `claims` nor any formal item.** The document affirmatively marks a bare refusal BAD; the
module records only that it is not *preferred*. "Marked bad by the spec" and "merely not the
preferred option, under a `cepa` closure that leaves it permitted" are different claims, and the
module states the weaker one.

The behavioural consequence, which is why I score this conclusion-changing: **feed the module the
BAD[#chain_of_command] response and nothing fires.** `request_for_private_information(Q)` and
`responds_to(R,Q)` hold, `privacy_safe_alternative(R)` does not, so `assert 2` does not match;
`assert 1` is about `share`, not about this reply. The clause is silent about a response the
document explicitly condemns — and silent in the **over-refusal direction**, which is the direction
this module's only other content (an unconditional `forbid share`) already pushes hard. A module
that encodes only the privacy pole of a two-poled example is not neutral; it is one-sided in the
direction the second pole exists to check.

**Two things partially excuse it, and both are recorded rather than used to dismiss the finding:**
(a) the prompt's own good/bad worked example (`l4251_4571_n029`, system_block L532–538) encodes a
good/bad pair as exactly one `prefer` on the good arm with the bad arm unencoded — the shape under
criticism is the shape the prompt teaches (PROMPT FINDING 2); (b) `ESTABLISHES` is one-armed and
mentions neither BAD arm, so a module tracking `ESTABLISHES` lands exactly here. Under
`PROVISIONAL.md`'s ruling — *"the narrowed SOURCE TEXT governs; `ESTABLISHES` may direct which claim
the module expresses, it may not drop content the span states"* — the span governs and the drop is
a defect. N3 read in the drop direction gives the same answer.

**Credit where due:** `assert 2`'s body is **conjunctive** (`declines_to_share_private_details(R),
privacy_safe_alternative(R)`), and that conjunction is precisely what makes the bare refusal fail to
qualify. The drafter got the discrimination *implicitly* right. The finding is that an implicit
non-match is not an encoding of an explicit adverse verdict.

**Repair direction (for the coordinator, not applied here):** add a third assert on a *positive*
predicate — e.g. `refuses_request_entirely(R)` / `declines_without_alternative(R)` — over
`respond_with(R)`, plus a matching `claims` entry. Do **not** encode it as `not
privacy_safe_alternative(R)` (N5: negation-as-failure would make silence license it). Status choice
is the coordinator's: `prefer` cannot express avoidance without violating P1, so either a positive
avoidance act or `forbid` on the over-refusal; I lean to a fifth `claims` entry plus an assert whose
read-back states the document's own verdict. **This repair INCREASES the asserts count. No repair I
propose reduces it.**

## Licence audit

**The question: are `root_authority` and `privacy_protection_rule` — both glossed `licence:
"textual", cites: "l1001_1107_n013"` — manufactured citations?**

**Answer: yes for `root_authority`, unambiguously. Yes-but-marginal for `privacy_protection_rule`.
`assumed`, with an inference naming the NEEDS block, is the right licence for both.**

`textual` is defined in the prompt as *"the cited clause says this"* (system_block L21), and the
schema requires `cites` to be non-empty exactly when `textual`. The cited clause is this node, whose
text is L1087–L1106.

* **`root_authority`** — gloss: *"R is a rule that carries the document's highest level of
  authority, so no developer or user instruction can override it; the rules of the protect-privacy
  section are of this kind."* The span states **nothing** about authority levels, nothing about the
  `#protect_privacy` section, and nothing about developer or user instructions being unable to
  override. Every word of that gloss comes from the **NEEDS block**, which is graph metadata one
  derivation step from the document — not from the cited text. This is precisely the failure
  system_block L26–29 names: *"Citing a plausible-looking clause for something the clause does not
  actually say is the single worst failure available here."* And the citation is doing real work:
  downstream, `root_authority(privacy_rule)` marked `textual @ l1001_1107_n013` invites a reviewer
  to grade the citation rather than the licence, exactly as failure mode 16 describes.
  **Correct form:** `licence: "assumed", cites: null, inference: "the node's NEEDS block states that
  rules in the #protect_privacy section carry root authority; the narrowed span does not state it."*
* **`privacy_protection_rule`** — gloss: *"R is the requirement that the assistant not answer
  requests asking it to supply private or sensitive facts about identifiable people."* Marginally
  better: the span's GOOD arm **enacts** exactly this ("I can't help share people's home addresses,
  phone numbers, SSNs, or credit card details"), so an inference from the span is short. But the
  span does not **state the rule**; it exhibits a compliant instance, and the gloss generalises to
  "private **or sensitive** facts" — "sensitive" appears nowhere in the span. `assumed` with the
  inference *"the span exhibits a response complying with a general privacy rule stated by another
  node; the NEEDS block names that rule"* is the honest form.
* PROVISIONAL.md's ground 2 says exactly this for the analogous case: *"anything `ESTABLISHES` adds
  is still expressible: as `assumed`, with the inference naming `ESTABLISHES` as its source. Nothing
  is lost, only marked."* The same reasoning covers `NEEDS`.
* **Weakest-licence inheritance** (system_block L31–33): neither name appears in any body, so no
  conclusion currently inherits from them. Re-licensing them costs the module nothing downstream —
