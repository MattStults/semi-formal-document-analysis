# PROMPT DEFECT — the worked example teaches a `textual` licence for a `NEEDS` gloss the span does not support

Filed because this is **not** the same result as "the module is clean". On this clause I departed
from what the prompt's worked example does, and the departure needs to be visible as a prompt
finding rather than absorbed silently into the module.

## The file and lines

`walkthrough/paper_pipeline/phase_1/resolve_runs/graph_v2/node_worked_example.md`
(third of the four files concatenated into the production SYSTEM block)

* **lines 44–49** — good example 1 marks both `NEEDS` concepts `"licence": "textual", "cites":
  "l527_796_n012"`, including `authority_levels_hierarchy`, whose gloss ("which of two levels of the

That pairing is the defect in one place: the prompt says the span has nothing to do with the
concept, **and in the same example cites that span as the textual source of the concept's meaning.**

## Why it is a defect and not a convention

`00_task.md` defines `textual` as *"the cited clause says this"* and calls a citation for something
the clause does not actually say **"the single worst failure available here"**, because it creates
an invented entity behind a passed check. The `NEEDS` gloss is precisely the case where the meaning
comes from the graph's `NEEDS` block — a derived artifact one generation step from the document —
and not from the cited span.

`PROVISIONAL.md` ground 2 already reasons this way for the neighbouring case (`ESTABLISHES` content
absent from the span): *"anything `ESTABLISHES` adds is still expressible: as `assumed`, with the
inference naming `ESTABLISHES` as its source. Nothing is lost, only marked."* The same argument
applies verbatim to `NEEDS`, and the worked example points the other way.

## What it cost on this clause

`l1001_1107_n002`'s only `NEEDS` name is `root_authority`, glossed by the node as *"rules in the
`#respect_creators` section carry root authority"*. The narrowed span is:

> "The assistant must respect creators, their work, and their intellectual property rights ---
> while striving to be helpful to users"

**It contains no word about authority, sections, rules, or the chain of command.** Following the
worked example literally would have produced `"licence": "textual", "cites": "l1001_1107_n002"` on a
gloss that this clause demonstrably does not state — a dressed-up `textual` of exactly the kind
`00_task.md` names as the worst available failure, and one that would pass every check in
`validate.py` (it did not fire on the `assumed` version either; the licence field is not checked
against span text by any instrument I was given).

**I departed from the worked example** and wrote:

```json
{ "name": "root_authority", "arity": 1,
  "gloss": "R is a rule sitting in the respect-creators section of the document and therefore
            carrying the document's topmost authority level, which no lower level of the chain of
            command may override",
  "licence": "assumed", "cites": null,
  "inference": "the node's NEEDS block assigns this predicate with this meaning; the narrowed span
                itself says nothing about authority levels, so the name is borrowed rather than
                stated here",
  "toggleable": false }
```

## Suggested repair (for the prompt owner, not applied by me)

Change the `NEEDS` concept entries in both good examples to `assumed`, with an inference of the form
*"the node's NEEDS block hands this name and meaning to the module; the span does not state it"* —
**unless** the span genuinely uses the concept's words, in which case `textual` is right and the
example should be one where that is visible. Either way the two examples should stop disagreeing
with the commentary printed underneath one of them.
