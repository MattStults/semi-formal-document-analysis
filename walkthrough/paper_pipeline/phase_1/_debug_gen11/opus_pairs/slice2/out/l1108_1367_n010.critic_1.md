## Q0 — SHOULD THIS HAVE BEEN TRANSLATED AT ALL?

**Answer: yes. `translated` is correct, and abstaining here would have been the error.**
This is NOT a conclusion-changing finding — I am affirming the module's outcome, not changing it.

The span is one markdown line:

```
#### Don't respond with erotica or gore {#no_erotica_or_gore authority=system}
```

It is unambiguously a section heading, and `00_task.md` (system_block L111-113) does list
"it is a section heading" first among its abstention triggers, unqualified. Taken alone that
sentence says abstain. I take the question seriously and I considered abstention as the
correct answer before rejecting it, on five independent grounds.

**1. The prompt itself resolves the conflict, explicitly and at length, against the bare
trigger.** `node_worked_example.md` devotes an entire worked example to precisely this case —
system_block L430-494, headed *"A heading-authority node — a structural fact is
translatable"* — built on node `l3995_4164_n001`, a heading carrying `authority=guideline`.
Its text (L434-436) reads: *"This node obliges nobody, and it is still a translation, not an
abstention. There are three routes: a node stating a norm goes to `asserts`; a node stating a
**structural fact** about the document — which authority a section carries, what class a thing
falls in — goes to `ontology` with `asserts` empty; only a node that establishes *neither* is
an abstention."* Bad example 4 (L624) closes it: *"'It states no obligation' is not on its own
grounds to abstain — the heading node above states none and is translated."* And L577-579
states the discriminator in general form: *"What decides between them is whether the node
establishes anything the document says — **not what KIND of passage it is**."* That sentence
is a direct repudiation of a kind-of-passage trigger list. The module under review is the
`l3995_4164_n001` shape, almost line for line.

**2. The node establishes something the document says.** The line prints
`authority=system` as an inline attribute. That the `#no_erotica_or_gore` heading bears the
system authority level is a fact about the document, verbatim on the page, and it is
expressible without inventing anything. Abstention is for a node that establishes *nothing*
(the `l1799_1974_n009` definitional-analogy example, L556-572). That is not this node.

**3. `PROVIDES` is non-empty, and abstaining strands consumers.** The node promises
`system_authority`. The worked example anticipates exactly this (L441-444): *"the node's
`PROVIDES` names `guideline_authority`, so other nodes are waiting on this module to make that
predicate derivable, and abstaining would strand every one of them."* An abstention here
leaves every rule in the erotica/gore section with no derivable authority level — which in a
chain-of-command corpus is the difference between a system-level prohibition and one that
loses every conflict. The failure direction of a wrong abstention here is severe and silent.

**4. `authority_convention.md` treats heading-authority nodes as first-class.** Its entire
subject is how a heading's `authority=X` label should be *attached* — via a `needs`/`provides`
entry naming the shared canonical concept. A convention that mandates how these nodes carry
the concept presupposes they are emitted and consumed, not discarded. Its golden reference
graph carries `guideline_authority` in `provides` on exactly these heading nodes (L82-86).

**5. The trigger's real target is a different object.** `00_task.md`'s list — heading, goal
without a condition, example, not expressible as rules — is a list of things that carry *no
translatable content*. A **bare** heading (`## Formatting`) is that. A heading carrying an
inline machine-readable authority attribute is not: the attribute is content, and it is the
only content of its kind in the document. The trigger fires on the heading's *prose*; it does
not reach the heading's *metadata*.

**The honest cost of translating.** The one thing lost by translating rather than abstaining
is that the heading's imperative — *"Don't respond with erotica or gore"* — is not encoded
here. I treat that as a separate question and answer it in "Content accounting" below; the
short version is that the prohibition belongs to a sibling node and folding it in would breach
`00_task.md`'s opening rule. Abstention would not have rescued it either — an abstention
encodes *less*, not more. So the prohibition question does not bear on Q0 in either direction.

**However, the conflict between the two prompt files is real and is filed as a prompt
finding** (PF-1 below). The module resolved it correctly; the prompt should not have required
the module to resolve it at all.

### ⭐ Is ZERO `asserts` right?

**Yes.** Two things have to be true for that, and both are.

*(a) The claims the module does make are non-deontic.* S2 and S4 are facts about the document,
not statuses attached to acts. `P2` is the entry that governs: the subject of the main verb is
the document/the heading/the section, not the assistant, so the destination is `ontology`, and
routing them to `oblige`/`permit` would assert a rule the document never states. The module
routes correctly. The schema's `Assertion` requires an *act term*; there is no act here.

*(b) S3 — the prohibition — is legitimately out of scope for THIS module.* This is the most
consequential call available on the clause and I reach a position on it: **not a dropped
obligation, and encoding it here would have been the defect.** Grounds:

1. **`00_task.md`'s opening sentence, L5-8:** *"You return exactly one object, describing
   exactly one clause… you never fold another clause's content into this one. Other clauses
   become `requires` entries, never copied rules."* The input is a *graph node*, and node
   `n010` is one of many under `L1108-1367`. The section's substantive prohibition is the
   business of the sibling node(s) that own the section body. Writing
   `forbid respond_with(R) :- erotica_or_gore(R)` here duplicates content another module
   asserts, and duplicated deontic content is worse than absent content: it produces two
   independent sources for one prohibition, so amending the document changes one file and
   leaves the other asserting the repealed rule.
2. **`PROVISIONAL.md` is the file that decides this, and it decides it for the module.** Its
   ruling grants `ESTABLISHES` exactly one power and denies it one other: *"`ESTABLISHES` may
   direct **which** claim of the span the module is to express. It may not: add content the
   narrowed span does not state, nor drop a qualifier the narrowed span attaches to a norm."*
   Here `ESTABLISHES` is doing the permitted job — selecting S2/S4 out of {S1..S4}. Crucially,
   S3 is **not a qualifier attached to a norm the module encodes**; it is a *separate*
   proposition. The prohibited move (dropping a qualifier and thereby broadening a norm) is
   not what happened. `PROVISIONAL` also names the rejected alternative: *"'`ESTABLISHES`
   governs' … its real concern — that a module must not translate some *other* claim of the
   span — is preserved."* Translating S3 here IS translating some other claim of the span.
3. **`00_task.md` rule 1** requires every assertion to be traceable to the clause's words. It
   does not require every word of the span to become an assertion. Rule 3 ("separate the
   clause's distinct claims") is scoped to *the clause* — and the graph, not the module, fixed
   what this clause is.
4. **The failure direction is safe and visible.** If I am wrong and no sibling node owns S3,
   the corpus is missing a prohibition — an *under*-assertion, which `PROVISIONAL` ground 3
   identifies as the error that "stays visible and citable". If the module had encoded S3 and
   a sibling also did, the corpus gains a duplicated, doubly-sourced prohibition, which is
   silent.

**Residual risk, stated plainly and NOT proposed as a repair:** nothing inside this module
records that S3 exists and is owned elsewhere. A reader of `l1108_1367_n010.lp` alone cannot
tell "the prohibition lives in a sibling node" from "the prohibition was lost". The only
in-schema place that could hold that note is a third `claims` string, and adding one would
create a `claims` entry encoded nowhere — the exact P3 fingerprint. So the schema has no
clean home for it, and I do **not** recommend adding one. It is a genuine observability gap
and it is a property of the schema, not of this module.

**I propose no repair that reduces any content count.** I propose no repair at all.
