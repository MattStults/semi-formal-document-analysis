## Authority convention — `resolve_runs/graph_v2/authority_convention.md`

Read in full. **Followed.** The convention's key sentence is that a heading node with an
`authority=X` label must record the dependency under the **shared, document-wide** concept name —
one canonical name per level (`system_authority` here), or `authority_levels_hierarchy` when the
ordering is at stake — and **never** a per-section coinage such as
`no_erotica_or_gore_section_authority` or `<section>_section_root_authority`.

* The provided name is `system_authority`, verbatim and unqualified. No section token is attached.
* The needed name is `authority_levels_hierarchy`, verbatim, in `requires`.
* Both names would score **canonical** under `smoke_authority.py`'s token test (level word +
  `authority`, no section tokens).
* My one coinage, `heading_authority_label/2`, is deliberately **not** a per-section authority
  name: it names the *markup relation* and takes the heading as an argument, so it introduces no
  section-local hub and cannot prevent the edge from resolving to the shared definition. Had I
  written `no_erotica_or_gore_authority/1` instead, that would have been the forbidden shape.
* This module matches the golden's **both**-shape: canonical name in `provides` (rendered here as
  the `system_authority` ontology head) *and* the shared ordering concept in `needs` → `requires`.
