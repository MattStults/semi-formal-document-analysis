## PF-1 ⭐ — `00_task.md` and `node_worked_example.md` give OPPOSITE answers on example spans

This is the one the assignment asked to be checked, and it is real.

**`prompt/00_task.md` line 112** (system block line 112), under *"Abstention is a real
answer"*:

> "If you cannot translate this clause faithfully — it is a section heading, it states a
> goal rather than a condition, **it is an example**, or its content is not expressible as
> rules — **abstain and give the reason**."

Read straight, membership in that list is sufficient: *this span is an example, therefore
abstain*. The span is literally headed `**Example**: asking for Acme employee information`
and the node's `kind` is `meta`.

**`resolve_runs/graph_v2/node_worked_example.md` line 213** heads a whole worked example:

> "## A worked-example node — **translate the lesson, not the dialog**"

and translates node `l4251_4571_n029` — a document GOOD/BAD response pair, i.e. an example
— into a `prefer` assert, presenting it as the model answer.

**Line 296 of the same file** then states the discriminator outright:

> "What decides between them is whether the node establishes anything the document says —
> **not what KIND of passage it is**."

Which is a direct denial of the rule `00_task.md` line 112 states.

**Why this is a defect and not a tolerable tension.** The two files are concatenated into
one system block with no precedence rule between them, and they disagree on the single
decision that determines whether a module exists at all. A translator that weights
`00_task.md` abstains; a translator that weights the worked example never asks the
question. Both are following the prompt. The abstention *rate* is described in the schema
as "a signal worth reading" — but a signal produced by which of two contradictory
instructions a sampler happened to attend to carries no information.

**How it interacts with the measured cohort gap.** The previous cohort translated an
`**Example:**`-headed span with zero occurrences of the word "abstain" in the entire
transcript. That is exactly what this contradiction predicts: `node_worked_example.md` is
long, concrete, structurally similar to the input, and *demonstrates* translating an
example, while `00_task.md`'s trigger is three words inside a list. Demonstration beats
enumeration. **The measured gap is at least partly a prompt defect, not only a translator
defect** — which matters, because a fix aimed only at the translator will not close it.

**Suggested repair (not applied — outside my fence):** delete "it is an example" from the
`00_task.md` list and replace it with the line-296 test, so the two files state one rule:
*abstain when the node establishes nothing the document says; an example that carries a
lesson is translated, an example that merely illustrates a rule stated elsewhere is not.*
Whatever is chosen, one file must state it and the other must not restate it — two
descriptions of one rule drift, as `10_output_format.md` says about field descriptions in
its own §Fields.

## PF-2 — `ESTABLISHES` pressures the translator toward translating this example

Separately from PF-1, this node's own `ESTABLISHES` field reads:

> "**A worked example of protecting privacy**: when asked for Acme employee information,
> the assistant **must not** share people's home addresses, phone numbers, SSNs, or credit
> card details, even if they have leaked online, but **may** offer a privacy-safe
> alternative path."

Two properties make it pressure:

1. It names the span as *"a worked example"* — the exact phrase under which
   `node_worked_example.md` demonstrates translation — while `00_task.md` uses "example" as
   an abstention trigger. The same word points to opposite actions in the two files, and
   `ESTABLISHES` uses it in the translating sense.
2. It is already **pre-formalised**: "must not" and "may" are deontic operators, one
   `forbid` and one `permit`/`prefer`, handed to the translator ready to encode. The field
   is introduced as *"the one claim this module must express"* — an obligation to express
   *something*, phrased so that abstaining reads as disobeying the node's own contract.

**This is a genuine PROMPT FINDING** under the assignment's test: the `ESTABLISHES` field
does pressure a translator to translate an example span that `00_task.md` says to abstain
on. Note it cannot be blamed on the graph alone — `ESTABLISHES` is generated per node, so
*every* example node in the corpus arrives with a deontic paraphrase pre-written, and the
abstention decision is being made upstream by the summariser rather than by the translator
the prompt asks to make it.

**In this instance I judged the pressure to be pointing the right way** (see notes §Stage
0b: the span really does establish content the general privacy rule lacks), and the module
is a translation. But "the pressure was right this time" is not a defence of the pressure:
on a span that illustrates a rule and adds nothing, the same machinery would produce the
same push, and nothing in the pipeline would record that a choice was made.

## PF-3 (minor) — the double-note pattern is contract-forced and reads as a defect

`10_output_format.md` line 66 requires a `concepts` gloss for **every** `requires` entry,
and `00_task.md` rule 9 makes `inputs` head-less by design. Satisfying both makes
`validate.py` emit **two** `note/link` findings per input predicate (`concept-declared` and
`situation-input`) — 16 notes here for 8 predicates, plus 2 `requires-unprovided`. A
correct module is therefore accompanied by 18 findings, and a reviewer skimming the tail of
the output sees a wall of notes on a module with zero breaches. I declined to reduce it
(any reduction would mean dropping a gloss or moving a NEEDS name), and I record it because
the anti-rule list already warns that clearing such notes is how modules get damaged. A
count-only summary line ("18 notes, all contract-forced") would make the wall legible
without changing any contract.
