# Pre-registration — deleting the licence-emphasis line from `00_task.md`

**Written before any call was made. The estimate had not yet been printed when the
prediction below was fixed.** Frozen 2026-08-07.

---

## The change

`prompt/00_task.md` line 17, deleted, and nothing else:

> This is the most important rule here, and it is **not** "only write what the text says".

You asked for the deletion and said it needed a way to measure the impact first. This is
that measurement.

Arm B is **generated**, not copied: `eval_arms/make_arm.py` deletes the line from the live
file and refuses unless it occurs exactly once and nothing else differs. A hand-made copy
would drift from the original the first time anyone edits it, and the run would then
measure that drift under this line's name. 11 tests, including one that pins the line is
present exactly once in the live prompt — if it fails, this document is measuring
something else.

⚠️ The generator writes **no provenance header into the file**. A `<!-- generated by -->`
comment is one more line of system prompt than arm A has, which would make the diff two
lines wide while this document says one. Provenance is in a sidecar the model never sees.

Assembled system blocks: **28,091 chars (A) vs 28,002 (B)** — 89, the line and its newline.
The two configs differ in `prompt.system_files`, `prompt.unused_files` and `prompt._arm`,
and in nothing else (checked key by key across the flattened configs).

## The prediction ⭐ FROZEN

**Deleting it will not change licence behaviour.** The graded taxonomy is stated twice
more — in the table immediately below this line, and in the `Licensed` field descriptions
in the schema the model also receives. If the sentence is redundant emphasis, the licence
mix moves less than the noise band.

**If deletion does move the licence numbers, that sentence was carrying more than the
table**, and the deletion is the wrong call regardless of how it reads.

⛔ Both outcomes are publishable here. This is registered so that "no significant
difference" cannot be re-read afterwards as "the harness was too small", and so a movement
cannot be re-read as "we expected that".

## The eval set — and why it is not the diagnosis set

Six clauses, **none ever sent to the model**, selected before any outcome was known by
sha256 of the id under a fixed salt:

| | | |
|---|---|---|
| m0445 | conditional | avoid_overstepping |
| m0544 | conditional | be_thorough_but_efficient |
| m0495 | conditional | be_clear |
| m0531 | conditional | formatting |
| m0293 | definitional | protect_privileged_information |
| m0055 | definitional | definitions |

**Stratified 4 conditional / 2 definitional, deliberately.** The corpus is 188 conditional
to 84 definitional, and an unstratified draw of 6 returned 5 definitional and 1
conditional. `asserts` — the only place a licence instruction has room to move anything —
lives on the conditional side, so an unstratified draw would have measured this question
mostly on clauses that cannot answer it. The salt, the strata and the exclusions are in
`heldout.provenance.json`.

The prompt was diagnosed on m0014, m0036, m0079, m0105, m0134, m0136, m0150, m0165. **None
of those appear above.** A prompt change validated on the clauses that motivated it is
fitting, which this project has a standing ruling against.

## ⚠️ What this measurement cannot settle, stated in advance

1. **The licence metric may be underpowered.** It scores licensed items in modules that
   validated, and on the last run only 3 of 8 first attempts validated at all. At ~40%,
   six clauses × three repeats gives roughly seven scored modules per arm. If
   `licence_modules_scored` comes back low, **the honest reading is "not measured", not
   "no difference"** — and the metric reports that count first, precisely so the two cannot
   be confused.
2. **n = 6 clauses, 3 repeats.** This can detect a large effect. It cannot rule out a small
   one, and I will not report it as having done so.
3. **First attempt only.** The repair loop launders a bad prompt; the question is what the
   prompt produces before anyone corrects it.
4. **One model, one temperature (0.2).** Nothing here generalises past
   `DeepSeek-V4-Flash-0731`.

## What would make me delete the line anyway

If licence behaviour is unmoved **and** `findings_per_clause` is unmoved, the line is doing
nothing measurable and the deletion is free. If either moves against arm B, it stays, and
the movement is the finding.

## Cost

Six clauses × 3 repeats × 2 arms = **36 calls, first attempt only** — `eval.py` refuses to
make a second call per clause. The estimate is printed and gated before anything is sent,
against the config's $0.25 ceiling and the project's $8.50 cap. This directory has spent
~$0.14 to date.

## Reproduce

```bash

   --out 00_task_no_emphasis.md
$V eval.py --clause-file eval_arms/heldout.txt --repeats 3 \
   --compare config_arm_b.json --metric licences \
   --out eval_arms/RESULT_licence_emphasis.json --live
```
