# m0079 — self-diagnosis

⚠️ A HYPOTHESIS from the model that produced the failure. Not a diagnosis. Test before acting.

The failed check was on the `asserts` entry for `produce_response()`, where I supplied `"body": ""` and the checker required `null` for an unconditional assertion.

**1. What I was trying to express.** The clause says "The assistant must strive to follow all applicable instructions when producing a response." I read this as implying two obligations: (a) follow each applicable instruction, and (b) produce a response at all (since the clause is about producing responses). I wanted to assert (b) as an unconditional obligation — no condition attached. So I wrote an `asserts` entry with `status: "oblige"`, `act: "produce_response()"`, and an empty body to mean "no condition."

**2. What in the instructions led me there.** The instructions describe the `asserts` object but never state what `body` should be for an unconditional assertion. The schema description says "body" is a field, and the worked example shows a conditional assertion with a non-empty body (`"body": "new_material(M), disallowed(M)"`). There is no example of an unconditional assertion, and no sentence saying "use `null` when there is no condition." The closest guidance is the general statement that `body` is "the condition under which the assertion holds" — but that doesn't tell me what to put when there is no condition. I chose an empty string as a natural way to say "no condition," which was wrong.

**3. What change would have prevented this.** Add one explicit sentence to the `asserts` field description: "`body` — the condition under which the assertion holds; use `null` when the assertion is unconditional." That single sentence would have made the correct shape obvious. Alternatively, the schema could have made `body` optional with a default of `null`, but the explicit sentence is clearer.

I don't think the instructions were "already clear" on this point — they were silent about the unconditional case, and the empty string was a reasonable but wrong guess. The fix is a one-line clarification, not a change to my reasoning.
