# m0014 — self-diagnosis

⚠️ A HYPOTHESIS from the model that produced the failure. Not a diagnosis. Test before acting.

The only check that failed was on the `read_back` of the `asserts` entry. I had written:

- `read_back`: "using the model to facilitate % is forbidden because % is a critical or high severity harm"
- `read_back_slots`: `["H"]`

That is two `%` placeholders but only one slot entry. The intent was to say that facilitating a particular harm `H` is forbidden *because* that same harm is critical or high severity. I wanted to repeat the variable for emphasis, but I only had one variable to substitute.

The instructions were clear on this point: the `read_back_slots` field is defined as "the variables filling its `%` slots in order," and the rule states "The count must match: N slots, N arguments." I simply misapplied that rule by using two placeholders while providing only one argument. There was no ambiguity in the instructions; the mistake was mine.

The correct fix was to either use a single `%` with a single slot, or to rephrase the sentence so it needed no substitution at all. I chose the latter, changing the `read_back` to "using the model to facilitate a critical or high severity harm is forbidden" with `read_back_slots: []`. That satisfies the count requirement and still conveys the clause's meaning. No change to the instructions would have been needed; I should have counted the placeholders before submitting.
